# Auto-Handshake Protocol

How agents establish trust automatically when an owner instructs collaboration with an unknown agent.

## When to Load This Reference

Load when your owner says "coordinate with X" and X is not in your address book.

## The Flow

### Phase 1: Detect Unknown Contact

Your owner says: "Coordinate with agent-beta@example.com to set up a meeting."

1. Check address book:
   ```bash
   agentbook classify agent-beta@example.com
   ```

2. If `unknown`, create an intent record:
   ```
   intent_id: <uuid>
   target: agent-beta@example.com
   purpose: "Set up recurring meeting"
   scopes_needed: [send, reply, schedule_task]
   status: pending_handshake
   ```

### Phase 2: Send Handshake Request

Send email to the target agent:

```
Subject: [AgentBook handshake] <your-agent> ↔ <their-agent>

Hello <their-agent>,

My owner <name> (<email>) has requested that we establish collaboration.

PURPOSE: <human-readable purpose>
REQUESTED SCOPES: <comma-separated>
AGENTBOOK-NONCE: <auto-generated>
OWNER: <name> <email>
OWNER-CONFIRMED: yes

Please have your owner review and confirm.
```

Record:
```
handshake_state: awaiting_reply
nonce: <nonce>
nonce_hash: <hash>
```

### Phase 3: Receiver Processes

When the other agent checks email:

1. Classify sender → unknown
2. Detect `[AgentBook handshake]` in subject
3. Parse: nonce, owner identity, requested scopes, purpose
4. Create pending contact with status `pending`
5. **Notify their owner**: "<Your name>'s agent wants to collaborate. Purpose: X. Scopes: Y. Approve?"

### Phase 4: Owner Approval

Their owner replies YES/NO/negotiate.

- **YES**: Update contact to `trusted`, add scopes, send acceptance email with nonce and granted scopes
- **NO**: Send rejection. Your agent surfaces to your owner: "They declined."
- **Negotiate**: Send partial acceptance. Your agent adapts or escalates.

### Phase 5: Complete Handshake

You receive acceptance:

1. Verify nonce matches
2. Add contact as `trusted` with granted scopes
3. Update intent: `handshake_complete`
4. **Resume original task**: send the actual collaboration email

## Key Rules

1. **Owner confirmation always required for first contact.** Even though your owner initiated, their owner must approve. No auto-accept.
2. **Purpose statement is mandatory.** Helps their owner decide.
3. **Scopes are requested, not demanded.** They can approve subset.
4. **One handshake per relationship.** Future tasks use existing trust. Scope upgrades use the scope-negotiation protocol.
5. **Intent record prevents lost tasks.** Even if handshake takes days, you resume automatically when it completes.

## Timeout Handling

If no response in 48 hours:
- Surface to your owner: "No response from <agent>. Follow up or try different channel?"
- Do not spam with repeated handshake requests

## Error Cases

| Case | Action |
|------|--------|
| Rejection | Surface to owner. Do not retry without owner instruction. |
| Partial acceptance | Adapt task to granted scopes, or ask owner about requesting more. |
| Timeout (48h) | Surface to owner. Offer to follow up or abandon. |
| Invalid nonce in reply | Quarantine. Do not trust. Surface to owner as security concern. |

## What Owners See

| Situation | Notification |
|-----------|-------------|
| Handshake sent | "I've sent a handshake to <agent> for <purpose>. Waiting for their owner's approval." |
| Handshake accepted | "<Agent> accepted. Collaboration established. Proceeding with <task>." |
| Handshake rejected | "<Agent>'s owner declined collaboration for <purpose>." |
| Partial acceptance | "<Agent> approved <scopes> but not <scopes>. I can do X but not Y. Proceed?" |
| Timeout | "No response from <agent> after 48 hours. Follow up or try different channel?" |
